================================================================================
1. APA ITU MALURLGUARD?
================================================================================

MalUrlGuard adalah sistem klasifikasi URL berbasis Machine Learning yang
mendeteksi apakah sebuah URL berbahaya atau tidak secara otomatis.

Sistem ini bekerja dengan cara menganalisis STRUKTUR URL itu sendiri tanpa
perlu mengakses atau membuka halaman website tersebut. Ini disebut pendekatan
"lexical feature extraction" — hanya membaca karakter dan pola pada URL.

CONTOH KASUS NYATA:
  - Jaringan WiFi kampus menerima request ke URL mencurigakan
  - Sistem MalUrlGuard menganalisis URL tersebut dalam < 100ms
  - Hasilnya: "phishing" dengan confidence 87%
  - URL diblokir secara otomatis oleh firewall/proxy
  - Mahasiswa tidak jadi korban phishing

KEUNGGULAN DIBANDING METODE MANUAL:
  - Kecepatan: analisis dalam milidetik (bukan menit/jam)
  - Skala: bisa proses ribuan URL per detik
  - Offline: tidak butuh koneksi ke cloud service berbayar
  - Explainable: bisa dijelaskan KENAPA URL dianggap berbahaya
  - Ringan: bisa jalan di Raspberry Pi 4 untuk edge deployment

================================================================================
2. FUNGSI UTAMA
================================================================================

FUNGSI 1 — KLASIFIKASI URL (CORE FUNCTION)
  Menerima satu URL dan mengembalikan:
  - Label: benign / phishing / malware / defacement
  - Confidence: seberapa yakin model (0.0 - 1.0)
  - Probabilitas: distribusi kemungkinan ke semua kelas
  - Latency: waktu proses dalam milidetik

FUNGSI 2 — BATCH CLASSIFICATION
  Menerima banyak URL sekaligus (dari file CSV atau API call)
  Berguna untuk: audit log jaringan, scan database URL, forensik

FUNGSI 3 — FEATURE EXTRACTION
  Mengurai URL menjadi 41 fitur numerik:
  - Panjang URL, hostname, path, query
  - Jumlah karakter khusus (titik, strip, underscore, slash, dsb)
  - Deteksi IP address sebagai hostname
  - Deteksi simbol @ (teknik obfuscation klasik)
  - Entropy Shannon hostname (ukuran keacakan)
  - Deteksi kata kunci mencurigakan (login, verify, paypal, dsb)
  - Dan 30+ fitur lainnya (lihat Bagian 7)

FUNGSI 4 — EXPLAINABILITY (SHAP)
  Setiap prediksi bisa dijelaskan: "URL ini dianggap phishing karena..."
  - Fitur mana yang paling berkontribusi pada prediksi
  - Arah kontribusi: meningkatkan atau menurunkan risiko
  - Berguna untuk: edukasi, audit, tuning model

FUNGSI 5 — REST API
  FastAPI server yang bisa diintegrasikan dengan:
  - Web application firewall (WAF)
  - Proxy server (Squid, Nginx)
  - Browser extension
  - SIEM platform (Splunk, ELK)
  - Mobile/web app internal

FUNGSI 6 — TRAINING PIPELINE
  Melatih ulang model dengan dataset baru:
  - Dataset sintetis (built-in, 10.000 URL)
  - PhishTank (perlu API key gratis)
  - Dataset custom milik sendiri (format CSV)

FUNGSI 7 — DEMO DASHBOARD
  Antarmuka visual berbasis Streamlit untuk presentasi dan demo lab:
  - Input URL langsung di browser
  - Visualisasi confidence bar
  - Grafik distribusi probabilitas
  - Riwayat 10 prediksi terakhir

PIPELINE TRAINING (satu kali, sebelum deployment):

  [CSV Dataset]
       |
       v
  [Feature Extraction]  -- 41 fitur per URL
       |
       v
  [Train/Val/Test Split]  -- 80% / 10% / 10% stratified
       |
       v
  [Train RF] --> rf_model.joblib
  [Train XGB] --> xgb_model.joblib
       |
       v
  [Evaluate]  -- accuracy, f1, confusion matrix PNG
       |
       v
  [Persist]  -- models_pretrained/


PIPELINE INFERENCE (real-time):

  URL String
    --> extract_lexical_features()     ~1ms
    --> np.array (1x41)
    --> rf.predict_proba()             ~60ms
    --> xgb.predict_proba()            ~1ms
    --> ensemble.weighted_average()    <1ms
    --> SHAP explanation (optional)    ~5ms
    --> JSON response


KOMPONEN FILE:

  malurlguard/features/lexical.py
    Mengekstrak 41 fitur dari string URL menggunakan:
    - urllib.parse (parsing URL)
    - tldextract (TLD dan subdomain)
    - regex (deteksi IPv4, pola khusus)
    - math (Shannon entropy)

  malurlguard/features/extractor.py
    Orkestrasi: satu URL -> Dict fitur, atau List URL -> DataFrame

  malurlguard/models/random_forest.py
    Wrapper RandomForestClassifier scikit-learn
    class_weight='balanced' (handle imbalanced dataset)

  malurlguard/models/xgboost_model.py
    Wrapper XGBClassifier
    scale_pos_weight otomatis untuk kelas minoritas

  malurlguard/models/ensemble.py
    Soft voting: rata-rata tertimbang probabilitas dari semua model
    Default weight: RF=1.0, XGBoost=1.2

  malurlguard/training/dataset.py
    Load CSV, validasi, stratified split 80/10/10

  malurlguard/training/pipeline.py
    Orkestrasi training end-to-end

  malurlguard/training/evaluate.py
    Hitung metrics + plot confusion matrix

  malurlguard/inference/predictor.py
    Load model sekali, cache di memory, layani prediksi

  malurlguard/inference/explainer.py
    SHAP TreeExplainer untuk RF dan XGBoost

  malurlguard/api/main.py
    FastAPI app dengan CORS enabled

  malurlguard/api/routes.py
    Endpoint handlers (/predict, /predict/batch, /health, /metrics)

  malurlguard/api/schemas.py
    Pydantic schemas untuk validasi request/response

  malurlguard/cli.py
    Click CLI: download, train, predict, batch, serve, dashboard

  dashboard/streamlit_app.py
    Demo dashboard visual berbasis Streamlit

------------------------------------------------------------------------
5.2 TRAINING MODEL
------------------------------------------------------------------------

PERINTAH:
  malurlguard train --model all

ATAU tanpa CLI:
  python scripts/train_all.py

OPSI TAMBAHAN:
  --model rf        : Hanya Random Forest
  --model xgb       : Hanya XGBoost
  --model all       : Keduanya + Ensemble (DEFAULT)
  --data path/file.csv   : Pakai dataset lain (default: data/synthetic_urls.csv)
  --output folder/  : Simpan model ke folder lain (default: models_pretrained/)

CONTOH:
  malurlguard train --model all --data data/synthetic_urls.csv --output models_pretrained/

PROSES YANG TERJADI:
  1. Load CSV dataset
  2. Ekstraksi 41 fitur dari setiap URL
  3. Split data: 80% train, 10% validasi, 10% test
  4. Training Random Forest (100 pohon)
  5. Training XGBoost (200 boosted trees)
  6. Evaluasi pada test set (accuracy, F1, confusion matrix)
  7. Benchmark latency (mean, p50, p95, p99)
  8. Simpan model ke models_pretrained/

OUTPUT SETELAH TRAINING:
  models_pretrained/
  ├── rf_model.joblib              : Model Random Forest tersimpan
  ├── xgb_model.joblib             : Model XGBoost tersimpan
  ├── feature_names.json           : Daftar nama fitur
  ├── metrics/
  │   ├── metrics_rf.json          : Metric RF (accuracy, F1, dll)
  │   ├── metrics_xgb.json         : Metric XGBoost
  │   ├── metrics_ensemble.json    : Metric Ensemble
  │   ├── summary.json             : Ringkasan semua model
  │   ├── confusion_matrix_rf.png  : Visualisasi confusion matrix RF
  │   ├── confusion_matrix_xgb.png : Visualisasi confusion matrix XGBoost
  │   └── confusion_matrix_ensemble.png

CARA BACA OUTPUT TERMINAL:
  [rf] accuracy=0.9800 f1_macro=0.9750
   ^     ^                  ^
   |     |                  +-- F1-score rata-rata semua kelas (0-1, makin tinggi makin baik)

7. PENJELASAN FITUR (41 FITUR LEXICAL)
================================================================================

Semua fitur diekstrak HANYA dari string URL — tanpa koneksi jaringan.

KATEGORI A: FITUR PANJANG (5 fitur)
  url_length              : Panjang total URL
                            Phishing URL cenderung panjang untuk menyembunyikan domain asli

  hostname_length         : Panjang hostname (contoh: "paypal-secure-login.tk" = 22)
                            Domain palsu cenderung panjang dan aneh

  path_length             : Panjang path setelah domain
                            Phishing sering punya path panjang dengan parameter banyak

  query_length            : Panjang query string (setelah ?)
                            Banyak parameter = lebih suspicious

  fragment_length         : Panjang fragment (setelah #)
                            Jarang dipakai di URL legitim dengan cara mencurigakan

KATEGORI B: FITUR JUMLAH KARAKTER (14 fitur)
  num_dots                : Jumlah titik (.)
                            Contoh: "paypal.secure.login.com.evil.tk" = 5 titik = suspicious

  num_dashes              : Jumlah strip (-)
                            Contoh: "paypal-secure-verify-account.tk" = 3 strip = suspicious

  num_underscores         : Jumlah underscore (_)
  num_slashes             : Jumlah slash (/)
  num_equals              : Jumlah tanda sama dengan (=) — indikator banyak parameter
  num_questionmarks       : Jumlah tanda tanya (?)
  num_ampersands          : Jumlah & — indikator banyak parameter GET
  num_percent             : Jumlah % — URL encoding (sering dipakai untuk obfuskasi)
  num_at                  : Jumlah @ — teknik obfuskasi klasik phishing
  num_digits              : Jumlah angka dalam URL
  num_letters             : Jumlah huruf dalam URL
  ratio_digits_to_total   : Rasio angka vs total karakter
                            IP-based URL punya rasio tinggi

  num_special_chars       : Karakter non-standar di URL
                            Obfuskasi sering pakai karakter aneh

  num_query_params        : Jumlah parameter query
                            URL phishing sering kirim banyak data lewat query

KATEGORI C: FITUR DETEKSI POLA (10 fitur)
  has_ip_as_hostname      : 1 jika hostname adalah IPv4 (misal: 192.168.1.1)
                            SANGAT mencurigakan — URL legitim jarang pakai IP langsung
                            Contoh: http://185.220.101.5/update.exe

  has_at_symbol           : 1 jika URL mengandung @
                            Teknik obfuskasi: http://legitimate.com@evil.tk/
                            Browser akan mengunjungi evil.tk, bukan legitimate.com!

  has_port                : 1 jika URL pakai port non-standar (bukan 80/443)
                            Contoh: http://evil.tk:8080/payload

  has_https               : 1 jika scheme adalah https
                            Phishing modern juga pakai HTTPS, tapi ini tetap fitur relevan

  has_double_slash_in_path: 1 jika ada // di dalam path (bukan di scheme)
                            Teknik redirect tersembunyi

  has_punycode            : 1 jika hostname ada xn-- (IDN/Punycode)
                            Dipakai untuk spoof domain: xn--pple.com mirip apple.com

  has_https_in_hostname   : 1 jika kata "https" ada DI DALAM hostname
                            Anti-pattern klasik: http://https-paypal.com/login
                            Dirancang untuk menipu user yang baca URL sekilas

  has_suspicious_keyword  : 1 jika URL mengandung kata kunci berisiko
                            List: login, signin, verify, secure, account, update,
                                  confirm, banking, paypal, ebay, amazon, apple,
                                  microsoft, google, facebook, password, dll (30+ kata)

  suspicious_keyword_count: Jumlah kata kunci mencurigakan yang ditemukan
                            Makin banyak = makin suspicious

  has_double_slash_in_path: Deteksi open redirect via //target.domain

KATEGORI D: FITUR TLD DAN SUBDOMAIN (4 fitur)
  tld_length              : Panjang TLD (top-level domain)
                            .tk = 2, .co.id = 5, .com = 3

  tld_is_common           : 1 jika TLD dari daftar terpercaya
                            Terpercaya: com, org, net, id, co.id, ac.id, go.id, dll
                            Tidak terpercaya: .tk, .ml, .ga, .cf, .gq, .xyz, .pw

  num_subdomains          : Jumlah level subdomain
                            Contoh: sub1.sub2.evil.tk = 2 subdomain = suspicious

  subdomain_length_avg    : Rata-rata panjang token subdomain
                            Subdomain panjang dan acak = suspicious

KATEGORI E: FITUR ENTROPI DAN LINGUISTIK (7 fitur)
  shannon_entropy_hostname: Ukuran keacakan hostname (0 = sangat teratur, 5+ = acak)
                            Domain C2 (command-and-control) sering DGA = entropi tinggi
                            Contoh: "a3x9k2mq.evil.tk" = entropi tinggi
                            Contoh: "github.com" = entropi rendah

  shannon_entropy_path    : Ukuran keacakan path
                            Path dengan token random panjang = mencurigakan

  has_punycode            : (lihat di atas)
  percent_encoding_ratio  : Rasio % encoding dalam URL
  longest_token_length    : Panjang token terpanjang (split by . / - _)
  num_tokens              : Jumlah token setelah split
  max_consecutive_consonants: Konsonan berturutan maksimal di hostname
                              Kata gibberish punya banyak konsonan berturutan
                              Contoh: "kxzmvq.tk" vs "paypal.com"

  vowel_ratio             : Rasio vokal dalam hostname
                            Kata nyata: vokal ~40%, kata random: lebih rendah

KATEGORI F: FITUR DOMAIN (2 fitur)
  domain_length           : Panjang domain (tanpa TLD)
  registered_domain_length: Panjang domain terdaftar lengkap

8. PENJELASAN MODEL MACHINE LEARNING
================================================================================

MODEL 1: RANDOM FOREST
  Algoritma: RandomForestClassifier (scikit-learn)
  Cara kerja:
    - Membuat 100 "pohon keputusan" berbeda dari subset data dan fitur
    - Setiap pohon vote untuk kelas tertentu
    - Final prediction = mayoritas vote
    - Pohon-pohon yang berbeda mengurangi overfitting (ensemble learning)
  Parameter:
    - n_estimators = 100 (jumlah pohon)
    - max_depth = 20 (kedalaman maksimal tiap pohon)
    - class_weight = 'balanced' (kompensasi kelas minoritas)
    - n_jobs = -1 (pakai semua CPU core)
  Keunggulan: Robust, interpretable, feature importance built-in
  Kelemahan: Lambat untuk dataset besar, model file besar

MODEL 2: XGBOOST
  Algoritma: XGBClassifier (xgboost library)
  Cara kerja:
    - Membangun 200 pohon secara bertahap (boosting)
    - Setiap pohon baru fokus memperbaiki kesalahan pohon sebelumnya
    - Teknik regularisasi mencegah overfitting
  Parameter:
    - n_estimators = 200 (jumlah iterasi boosting)
    - max_depth = 8 (kedalaman lebih dangkal dari RF, mencegah overfit)
    - learning_rate = 0.1 (seberapa besar koreksi tiap iterasi)
    - scale_pos_weight = auto (kompensasi imbalanced class)
  Keunggulan: Sangat akurat, cepat (inference ~1ms), state-of-the-art tabular
  Kelemahan: Lebih susah di-tune, black-box tanpa SHAP

MODEL 3: ENSEMBLE (KOMBINASI)
  Metode: Soft Voting dengan bobot
  Cara kerja:
    - RF menghasilkan: [P(benign)=0.10, P(phishing)=0.80, P(malware)=0.06, P(def)=0.04]
    - XGB menghasilkan: [P(benign)=0.08, P(phishing)=0.72, P(malware)=0.14, P(def)=0.06]
    - Ensemble = RF*1.0 + XGB*1.2 dibagi total bobot (2.2)
    - Final: [benign=0.089, phishing=0.758, malware=0.102, def=0.051]
    - Kelas dengan probabilitas tertinggi = prediksi final
  Keunggulan: Lebih robust dari model tunggal, mengurangi variance
  Bobot XGB lebih tinggi (1.2 vs 1.0) karena latency lebih cepat dan akurasi
  sering sedikit lebih baik untuk tabular data

METRIK EVALUASI:
  Accuracy    : (Prediksi Benar) / (Total Prediksi)
                Mudah dipahami tapi bisa menyesatkan pada data tidak seimbang

  Precision   : (True Positive) / (True Positive + False Positive)
                Dari semua yang diprediksi phishing, berapa % yang benar phishing?
                Tinggi precision = sedikit false alarm

  Recall      : (True Positive) / (True Positive + False Negative)
                Dari semua phishing sesungguhnya, berapa % yang berhasil terdeteksi?
                Tinggi recall = sedikit yang lolos

  F1-Score    : 2 * (Precision * Recall) / (Precision + Recall)
                Harmonic mean dari precision dan recall
                Metrik paling fair untuk dataset tidak seimbang

  Confusion Matrix: Tabel prediksi vs actual per kelas
                    Bisa lihat di models_pretrained/metrics/confusion_matrix_*.png

EXPLAINABILITY (SHAP):
  SHAP = SHapley Additive exPlanations
  Menggunakan konsep dari game theory untuk menghitung kontribusi tiap fitur
  Cara baca output SHAP:
    - Nilai SHAP positif (+) = fitur ini MENINGKATKAN prediksi kelas saat ini
    - Nilai SHAP negatif (-) = fitur ini MENURUNKAN prediksi kelas saat ini
    - Nilai absolut |SHAP| = seberapa besar pengaruhnya
  Contoh interpretasi:
    has_suspicious_keyword = 1.0, SHAP = +0.312, direction = increases_risk
    Artinya: URL ini mengandung keyword mencurigakan, dan itu BERKONTRIBUSI BESAR
             terhadap prediksi "phishing"

9. PENJELASAN LABEL / KATEGORI
================================================================================

LABEL 0 — BENIGN (AMAN)
  Deskripsi: URL yang aman dan legitimate
  Contoh:
    - https://github.com/user/repo
    - https://telkomuniversity.ac.id/admission
    - https://tokopedia.com/product/123
    - https://wikipedia.org/wiki/Machine_learning
  Karakteristik URL benign:
    - Domain dikenal dan terverifikasi
    - HTTPS (biasanya)
    - TLD umum (.com, .org, .id, .ac.id)
    - Tidak ada kata kunci phishing
    - Struktur URL bersih dan dapat dibaca

LABEL 1 — PHISHING (PENGELABUAN)
  Deskripsi: URL yang menyamar sebagai situs legitimate untuk mencuri
             kredensial (username, password, data kartu kredit)
  Contoh:
    - http://paypal-secure-login.tk/verify.php?id=123
    - http://192.168.1.1@bankbca-secure.xyz/login
    - http://update-apple-id.cf/signin?next=/dashboard
  Karakteristik URL phishing:
    - Domain mirip brand terkenal tapi beda (paypal-secure.tk)
    - TLD murah/gratis (.tk, .ml, .cf, .gq, .xyz)
    - Mengandung kata kunci: login, verify, secure, account, update
    - Kadang pakai IP address sebagai hostname
    - Kadang pakai simbol @ untuk redirect tersembunyi

LABEL 2 — MALWARE (PENYEBARAN MALWARE)
  Deskripsi: URL yang mendistribusikan software berbahaya
             (virus, trojan, ransomware, spyware)
  Contoh:
    - http://185.220.101.5/update.exe
    - http://free-keygen.xyz/crack.bat
    - http://evil.ru/wp-content/uploads/shell.php
    - http://update-flash-player.net/flash_installer.exe
  Karakteristik URL malware:
    - Berisi ekstensi file executable (.exe, .bat, .ps1, .vbs, .dll)
    - Domain mencurigakan atau IP langsung
    - Path berisi kata: download, update, crack, keygen, patch
    - HTTP (bukan HTTPS)
    - Domain baru dan tidak dikenal

LABEL 3 — DEFACEMENT (PERUSAKAN WEBSITE)
  Deskripsi: URL yang mengarah ke halaman website yang telah dirusak oleh
             hacker, atau URL yang mengandung pola serangan web
             (SQL injection, path traversal, LFI/RFI, dsb)
  Contoh:
    - http://targetsite.go.id/hacked-by-TeamXsploit.html
    - http://victim.edu/index.php?id=1' OR 1=1--
    - http://target.com/.git/config
    - http://site.com/phpmyadmin/index.php
    - http://victim.org/?page=../../../../etc/passwd
  Karakteristik URL defacement:
    - Mengandung pola "hacked-by-" atau nama grup hacker
    - SQL injection patterns (%27, ' OR, UNION SELECT)
    - Path traversal (../../, %2e%2e)
    - Akses file sensitif (.git, .env, backup.sql, phpinfo.php)

CATATAN PENTING:
  Klasifikasi bersifat probabilistik, bukan absolut.
  Sebuah URL bisa punya ciri phishing sekaligus malware.
  Ensemble model memberikan probabilitas ke SEMUA 4 kelas.
  Kelas dengan probabilitas tertinggi yang menjadi prediksi final.

12. TROUBLESHOOTING
================================================================================

MASALAH: 'malurlguard' is not recognized
  PENYEBAB: Entry point CLI tidak terdaftar di PATH
  SOLUSI:
    pip install -e .
    Pastikan Scripts/ Python ada di PATH
    Atau gunakan: python -m malurlguard.cli [perintah]

MASALAH: ModuleNotFoundError: No module named 'tldextract'
  PENYEBAB: Dependencies belum terinstall lengkap
  SOLUSI:
    pip install tldextract shap xgboost scikit-learn

MASALAH: FileNotFoundError: No trained models found
  PENYEBAB: Model belum ditraining
  SOLUSI:
    1. python scripts/generate_synthetic.py
    2. malurlguard train --model all

MASALAH: Model loading sangat lambat (>2 detik)
  PENYEBAB: Normal di panggilan pertama — model dibaca dari disk ke memory
  SOLUSI: Panggilan berikutnya akan cepat karena model di-cache
          Untuk API server, model di-cache sejak startup

MASALAH: Akurasi rendah di URL tertentu
  PENYEBAB: Model dilatih dengan data sintetis, bukan URL nyata
  SOLUSI:
    1. Gunakan dataset PhishTank nyata (lihat Section 5.1)
    2. Tambahkan host-based features (DNS, WHOIS) dengan --host-features
    3. Tambahkan data dari jaringan kampus sendiri sebagai training data

MASALAH: URL malware diklasifikasikan sebagai phishing
  PENYEBAB: Wajar — URL malware berbasis IP memiliki fitur yang mirip phishing
            (IP sebagai hostname, suspicious keywords, TLD buruk)
  SOLUSI: Akan diperbaiki di Phase 2 dengan LSTM char-level model

MASALAH: UnicodeEncodeError saat print di Windows
  PENYEBAB: Terminal Windows (cmd/PowerShell) default encoding cp1252
  SOLUSI:
    set PYTHONIOENCODING=utf-8
    Atau gunakan Windows Terminal yang support UTF-8

MASALAH: SHAP explanation tidak muncul
  PENYEBAB: Package shap belum terinstall atau gagal import
  SOLUSI:
    pip install shap
    Sistem akan fallback ke feature importance manual jika SHAP gagal
